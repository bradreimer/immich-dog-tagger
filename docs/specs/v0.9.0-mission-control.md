# v0.9.0 Mission Control Foundation

## Goal

Make the web UI the primary operational control surface for Immich Dog Tagger.

Mission Control must allow the user to:

* see pipeline/job status
* see current and recent operations
* manually start pipeline operations
* observe progress
* retain job history
* operate the same underlying pipeline used by the CLI

The CLI remains supported as a maintenance and automation interface, but must share the same execution/orchestration layer.

## Scope

v0.9.0 establishes the persistent job and orchestration foundation and the Mission Control UI.

Pipeline operations in scope:

* scan
* detect
* embed
* classify
* learn
* sync
* full pipeline

## Architecture

The intended flow is:

```text
Browser
  -> FastAPI
  -> job service / runner
  -> existing pipeline services
  -> state.db
```

The CLI and future scheduler should use the same job execution layer.

`state.db` remains the source of truth.

## Non-goals

Do not add in v0.9.0:

* background scheduling
* notifications
* multi-user authentication
* distributed workers
* new ML models
* speculative abstractions
* replacement of existing pipeline implementations

Scheduling belongs to v0.9.1.

## Design constraints

* Preserve existing behavior.
* Reuse existing services rather than duplicating pipeline logic.
* Prefer small, typed services.
* Use dependency injection where consistent with the existing architecture.
* Persist job state so browser refreshes do not lose operational history.
* Make operations idempotent where the existing pipeline supports it.
* Do not introduce WebSockets solely for v0.9.0; polling is acceptable for initial live progress.
* Each ticket should be independently testable and should leave `./scripts/check.sh` passing.

## v0.9.0 Exit Criteria

* Mission Control is the application landing page.
* Jobs have persistent lifecycle state.
* Jobs can be inspected through the API.
* Jobs can be started from the web UI.
* Job progress is visible in the web UI.
* Existing CLI operations use the shared job runner.
* No normal pipeline operation requires SSH.
* Existing review functionality remains available.
* Full project validation passes.
